# Contributing

Thanks for helping keep this list useful. It stays good by staying small and honest, so the bar for entries is deliberate.

## Adding an entry

1. Fork the repo and edit `README.md`.
2. Put the entry in the right category, in alphabetical order by name.
3. Use exactly this format:

```
   - [Name](https://example.com) - What it does, in one sentence.
```

4. Run the checks locally:

```bash
   npm run lint
   npm test
```

5. Open a pull request. One entry per pull request is easiest to review.

## What gets accepted

An entry must be:

- **Real and working.** The link goes to something that exists and runs.
- **Maintained.** For code, a commit or release in the last 12 months. For services, still operating.
- **Useful to builders.** It solves a concrete problem for people writing software on Solana.
- **Plainly described.** One factual sentence. No marketing words ("best", "revolutionary", "leading" and similar). Say what it does, not how great it is.

## What gets rejected

- Token, memecoin or NFT promotions
- Referral links, affiliate links and paid placements
- Projects that are unmaintained or no longer work
- Duplicates of something already listed
- Descriptions that read like an advertisement

## If it is your own project

You can submit it. Say that you are connected to it in the pull request. It is judged on the same terms as everything else.

The maintainer's own projects are listed too, in alphabetical order with the rest. They are marked "(by the maintainer)" in the description, and the linter enforces it.

## Suggesting a new category

Open an issue describing the category and three entries that would go in it.

## Reporting a dead or misleading link

Open an issue or send a pull request that removes or fixes the entry.
